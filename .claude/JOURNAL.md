# Claude Code Journal

This journal tracks substantive work on documents, diagrams, and documentation content.

1. **Task - Unified embedded firmware template** (v1.0.12): Reworked copier-embedded-project into one template for Arduino, bare AVR, ESP32/ESP8266 and STM32 with a single structure and opt-in components<br>
    **Result**: Every render now carries the same Makefile, `src/` (or `main/` for ESP-IDF), `lib/core` (C/C++) or `src/lib.rs` (Rust), `test/host`, `test/harness`, `test/functional`, `resources/`, `references/` and `tools/`; only the build file and one adapter vary by toolchain. Added bare AVR in C, C++ and Rust, the shared pure-logic core, eleven components (notebooks, resources, references, data, simulator, docs, ci, agents, env-installers, device-bridge, ltspice), the ATtiny84 op-amp LTspice netlist and its ngspice test, and a capability matrix with a placement guide. Five rendered projects build and simulate: AVR Rust and Arduino under simavr, STM32 Rust and STM32Cube under QEMU `netduinoplus2`, ESP32 Arduino and ESP-IDF under Espressif's QEMU fork; ESP8266 stays HIL only. 51 acceptance criteria closed, 0 defects; `make test` 461 passed 5 skipped, `make test-toolchain` 9 passed, `make test-functional` 5 passed, `make lint` clean.

2. **Task - Environment installers and simulator tier** (v1.0.12): Made `envs/` the master for the lab firmware installers and merged the two STM32 environments<br>
    **Result**: `firmware-stm32.py` now installs Rust 1.99.0 with six Cortex-M targets, cargo-binutils, PlatformIO 6.2.0 with `ststm32` and both STM32Cube and Arduino frameworks, stm32flash, QEMU 11.1.2 built from source and ngspice 41; the ESP installer adds Espressif's QEMU fork, the AVR installer adds avr-gcc, avrdude, PlatformIO/atmelavr and simavr. `~/.local/lab-utils/envs` symlinks the four master files and `make envs-sync` copies them into `template/resources/envs/`; tests assert byte identity. Added `environment_scope` global/local and the `create_environment` target. QEMU USART mapping and the ESP flash-image padding were fixed in the harnesses.

3. **Task - Agent context and release procedure** (v1.0.12): Added self-management skills and a release process to the template and to every generated project<br>
    **Result**: The `agents` component renders `<repo>-device` and `<repo>-toolchain` skills plus `/release`; `post_gen` links every skill into `.claude/skills`. The toolchain skill gives a numbered first-run sequence, environment repair, simulator checks and the LTspice run (JSON fields, pass thresholds, `circuit.log`, direct `ltspice -b` and `ngspice -b`), written for a small executor model. Generated projects carry `VERSION` 0.1.0, `make increment_version`, `RELEASING.md`, a dated CHANGELOG heading and the `/release` workflow; `VERSION` and `RELEASING.md` are update-protected. The template repository gained `RELEASING.md`, `make increment_version` and `/release-copier-template`.

4. **Task - Platform lab-utils installer**: Wrote `install-embedded-lab-utils.py` to add the embedded installers and Copier template to the platform lab-utils tree<br>
    **Result**: The script clones or reads the template repository, copies `firmware_env.py` and the three platform installers into `/galaxalab/utils/lab-utils.user/envs/embedded/`, writes `templates/embedded-project.yml` with the GitHub URL, and inserts or replaces a marked "Embedded Development Environments" submenu under "Install Virtual Environments" in `/galaxalab/utils/lab-utils.yml`. Menu ids are absolute platform paths; no user account is read or written; the script runs as root, defaults to root, and is idempotent. Adversarial verification reproduced and fixed 13 failure modes (anchor bounds, rollback, ownership, markers, clone errors). The script lives at `@onedrive/install-embedded-lab-utils.py`, outside the repository.
